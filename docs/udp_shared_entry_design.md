# UDP 业务穿透共享入口方案（方案A · 定案）

> **决策（2026-09-29）**：业务层不分 TCP/UDP，统一走共享入口；隧道与端口彻底解耦，为更大集群做准备。
> **状态**：方案定案，待实施。本文为跨项目记录，各相关项目 docs 目录各存一份，内容一致。

## 一、背景与决策理由

- TCP 业务穿透已按「共享入口 + PROXY v2」演进：隧道**不绑定节点端口**，访客经 L4 网关进入，网关查数据端定位节点后拨节点共享入口端口（8122-8144），端口与隧道解耦，同节点多实例无绑定冲突。
- 现有 UDP 业务穿透（阶段4，已上线）为**专用绑定模式**：服务端直接 `bind 0.0.0.0:<remote_port>` 监听 UDP（`ssh/udp_forward.go`，mode=channel），访客可达节点端口，与「不绑定端口」架构方向矛盾。
- **定案**：UDP 业务穿透并入共享入口模型。不论业务层 TCP 还是 UDP，隧道一律不绑定节点端口；集群扩大时端口规划不再受节点端口资源约束。

## 二、目标链路

```
访客 → L4网关(10000-30000/UDP, flow表)
     → 查数据端(隧道归属节点 + 共享入口端口)
     → 节点共享入口 8122-8144/UDP（每包带 flow_id 小头）
     → 服务端按 flow_id 查路由表 → 复用阶段4 SSH channel 转发（mode=channel）
     → 客户端 udp_proxy → 本地 UDP 业务

回程：本地 UDP → 客户端 channel → 服务端(包带 flow_id) → 网关(flow表 NAT) → 访客
```

## 三、封装协议（关键设计）

1. **UDP 无连接，PROXY v2 无法只在首包携带**：首包丢失则整条流失去归属。不采用「首包 PROXY v2 + 后续裸包」方案。
2. **采用每包小头封装**：网关 ↔ 服务端的每个 UDP 包前加 `flow_id`（建议 4-8 字节）。
3. **网关持有 flow 表**：访客五元组 ↔ flow_id ↔ 目标节点共享入口地址；flow 由网关分配、空闲 **330s** 回收（对齐 L4LB udpflow / 服务端 QUIC 空闲语义）。
4. **保留 UDP 语义**：不重传、不排序、容忍丢包；服务端不 ack、不缓存。
5. **flow 建立时机**：网关收到新五元组首包 → 查数据端 → 分配 flow_id → 后续包直接封装转发（无需等服务端确认，服务端未知 flow_id 的包直接丢弃，由访客重触发）。

## 四、各项目改动清单

| 项目 | 现状 | 方案A 改动 |
|---|---|---|
| **nwy-layer4-gateway** | 无任何 UDP 代码 | 新增 UDP 监听 10000-30000 + flow 表（参照 nwy-layer4-balancer `lb/udpflow.go`）+ 查数据端 + 每包 flow_id 封装转发共享入口 UDP + 回程 NAT |
| **nwy_node_core_server_go** | TCP 共享入口已完成（PROXY v2）；UDP 为阶段4专用绑定 | 共享入口监听器增加 UDP socket；按 flow_id 查路由表 → 复用 `udp_forward.go` 的 channel 转发；回程包带 flow_id |
| **nssh（客户端）** | `udp_proxy.go` 帧协议 + flow 表 + 数据面循环已上线（channel 模式） | **无改动**（SSH channel 层协议不变，QUIC/TCP 外壳均兼容） |
| **nwy-data-server** | `forward_protocol`（tcp/udp/both）已全链路 | 查询响应补充共享入口 UDP 端口与 protocol 标记（评估复用现有 shared entry 字段） |
| **sshd_manage** | forward_protocol 设置弹窗已上线 | 记录本方案；实施后更新 UDP 隧道口径文案（不再有节点直连端口语义） |

## 五、安全组影响（实施时同步）

| 位置 | 规则 | 用途 |
|---|---|---|
| L4 网关公网 | `UDP 10000-30000` | UDP 业务访客入口 |
| 节点内网 10/8 | `UDP 8122-8144` | 网关 → 共享入口 UDP |
| （过渡期）节点 | `UDP 10000-30000` | 专用绑定模式仍被访问的窗口期 |

## 六、过渡与共存

- 阶段4 专用绑定模式继续可用，**双模式并存**（与 TCP 共享入口当年灰度路径一致）。
- 新建 UDP 隧道默认走共享入口（数据端标记路由模式），存量专用绑定隧道按批次迁移后下线直连监听。
- `forward_protocol=udp/both` 的隧道配置字段语义不变，仅数据面路由变化。

## 七、待定问题

1. flow_id 空间与冲突策略；网关重启后 flow 表重建（访客重新触发即可）。
2. 多网关/高可用下 flow 漂移：访客换网关 → 新网关重新查数据端建流，需保证幂等。
3. MTU：封装开销（4-8B/包）挤占业务载荷，评估是否需要路径 MTU 探测。
4. 数据端查询协议：共享入口 UDP 端口是配置静态返回还是随隧道动态下发。
5. 服务端共享入口 UDP socket 的收包性能（单 socket vs 每实例 socket，参照 TCP 共享入口的多实例端口策略）。
